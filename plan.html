🦀 grafana-cli v0.1.0 shipped

A Rust CLI for the Grafana HTTP API — list/search dashboards, render panel charts inline, and emit reproducible PromQL scripts. Authenticated with a service-account token from --token, GRAFANA_SERVICE_ACCOUNT_TOKEN, or a config file.

4. Auth & URL Resolution

Implemented in config.rs::resolve() and main.rs::dispatch(). Precedence (first match wins):

Token

  1. --token <TOKEN>
  2. GRAFANA_SERVICE_ACCOUNT_TOKEN env
  3. profiles.<name>.token in config file

URL

  1. --url <URL>
  2. profiles.<name>.url
  3. grafana_url from cache map written by previous init (fallback)

init writes url and default_profile into ~/.config/grafana-cli/config.toml so future shells need only the env-var token. The token itself is never persisted.

5. Init Flow (config-map bootstrap)

  1. GET /api/health — print version + DB status
  2. GET /api/folders — slugify titles, build folder map
  3. GET /api/search?type=dash-db&limit=5000&page=N — paginate until empty
  4. GET /api/datasources (unless --no-datasources)
  5. For each dashboard (unless --shallow): GET /api/dashboards/uid/{uid} in parallel (default 8, configurable), count panels, collect referenced datasource UIDs
  6. Sort dashboards by title, serialize to ~/.config/grafana-cli/cache/<profile>.toml
  7. Update config.toml with the URL (and default_profile if unset)

Typical bootstrap time on a real instance with a few hundred dashboards: ~10–15 s end-to-end.

6. Chart Rendering (the rabbit hole)

Originally planned with textplots. After it produced a blank canvas for our data, we discovered two problems:

  • Display quirk — Chart::to_string() only renders axis labels; the canvas pixels are only filled when display() (which calls axis()+figures()) runs.
  • Lifetime trap — Chart::lineplot(&'a mut self, &'a Shape) ties the chart's mutable borrow to the shape's lifetime, so you can't call axis()/figures() on a chart bound to a local variable.

We replaced it with a small hand-rolled 100×24 grid renderer in render::chart::render_ascii. Multi-series Prometheus responses are aggregated per timestamp into min/mean/max bands, so a 135-broker CPU panel reveals spread instead of crisscross noise:

7. Template-Variable Resolution

Implemented in commands/panel.rs:

  • build_var_map(dash) — walks templating.list[].current.value; flattens single-element arrays; converts Grafana's magic "$__all" to the variable's allValue (or .* as a safe regex fallback).
  • expand_vars(s, vars) — substitutes $name, ${name}, and ${name:format} references, leaving unknown vars untouched.
  • resolve_ds_uid(raw, vars, cache_map) — handles $datasource / ${DS_PROMETHEUS} references, then falls back to the first prometheus datasource in the cache.

This was added after the first generate chart attempt returned "Data source not found" and the second returned a query with literal $instance=$__all in it.

9. Lessons Learned (Pitfalls Hit)

  1. textplots Display+lifetime quirks — replaced with a hand-rolled grid renderer.
  2. Grafana stores "$__all" literally in current.value — substitute via allValue or .*.
  3. Panel datasource.uid is often a template variable (e.g. ${DS_PROMETHEUS}) — always run through resolve_ds_uid.
  4. macOS config path resolves to ~/Library/Application Support/grafana-cli/, not ~/.config/.... Docs say XDG-style for portability.
  5. init persists url into the config file but never the token — keep secrets in env/keychain.
  6. /api/search caps at 5000 results/page; paginate with page=N until empty.
  7. When passing Shape::Lines(&data) inline, bind it to a let first — the temporary dies at the semicolon.
  8. Drawing one polyline per series for 100+ series produces visual noise that hides the line. Always aggregate.
  9. FuturesUnordered with seed+refill gives predictable progress output (25/347, 50/347, …); buffer_unordered reorders.
  10. Non-Prometheus panels print a skip: line and continue — never abort the whole dashboards view.
